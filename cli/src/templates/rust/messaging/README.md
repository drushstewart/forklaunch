# {{{name}}}

Durable, tenant-bound SMS messaging. Internal `/sms` and `/sms/:id` routes use TypeScript-compatible request HMAC authorization. Compliance export and erasure require a verified asymmetric JWT with the `system` role. The subject is the recipient phone number, matching the TypeScript module's `SmsRecord.to` selector.

Run `cargo run -p {{{name}}} -- --migrate` with a schema-owner database URL. Use a separate runtime role without SUPERUSER/BYPASSRLS, with schema USAGE, SELECT/INSERT/UPDATE/DELETE on `fl_messaging.sms_records`, and INSERT on `fl_messaging.pii_read_audit`. Forced RLS and explicit predicates bind every operation to the trusted `TENANT_ID` configuration. SMS contents, metadata and provider errors are encrypted with tenant-derived keys; plaintext reads require a successful audit insert. Retain previous keys through `LEGACY_ENCRYPTION_KEYS` during rotation. Do not log message contents or credentials.

{{#twilio}}The Twilio provider performs one REST dispatch attempt, with no implicit retry. A transport or persistence failure can occur after Twilio accepted the message; retrying blindly can duplicate delivery. Provider HTTP failures persist a failed record. `/webhook` verifies `X-Twilio-Signature` over every form field and the exact configured HTTPS `TWILIO_STATUS_CALLBACK_URL`; it does not trust Host or forwarded headers. Configure this URL identically at the provider. Callback state follows the TypeScript provider: last callback wins, unknown statuses become queued, and missing ErrorMessage clears prior errors. Twilio signatures do not prevent replay; repeat callbacks are accepted.{{/twilio}}
{{^twilio}}The base provider records a message as sent without contacting a carrier, matching the TypeScript hooks-only provider. Configure the Twilio module for actual delivery.{{/twilio}}

Start with `cargo run -p {{{name}}}`. Optional OTLP export uses standard `OTEL_*` settings. Offline contract/OpenAPI exports run before reading live database, authentication or provider configuration. Custom router extensions within builtin modules and shared TypeScript/Rust database migrations remain separate parity work.
