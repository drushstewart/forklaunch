# {{{name}}}

Tenant-bound persistent billing with thirty plan, subscription, checkout session, payment link and billing portal operations, compliance and health. Internal routes use request HMAC; billing portal routes require an asymmetric JWT with the `admin` role. HTTP and Streamable HTTP MCP share the listener and authentication rules. MCP defaults to `/mcp`; configure `MCP_ENABLED`, `MCP_PATH`, `MCP_ALLOWED_HOSTS` and `MCP_ALLOWED_ORIGINS` as needed.

Apply `cargo run -p {{{name}}} -- --migrate` with a schema owner. Run the service with a separate role without SUPERUSER/BYPASSRLS: schema USAGE and SELECT/INSERT/UPDATE/DELETE on `fl_billing.records`, plus INSERT on `fl_billing.sensitive_read_audit`. Every read uses the configured tenant and audits the verified actor. Provider data and opaque session URIs use tenant-derived encryption. Retain previous keys with `LEGACY_ENCRYPTION_KEYS` during rotation.

Checkout/payment-link/portal records use a ten-minute PostgreSQL TTL cache. Set `BILLING_DATABASE_BACKUP=true` for durable backups. Provider session expiry remains separate from cache expiry. Plans and subscriptions are durable.

{{#stripe}}The provider performs authenticated Stripe API requests pinned to the repository SDK version. `stripeFields` contains provider request fields and response objects. Provider calls precede local persistence; external effects can need reconciliation after transport or database failures. Plan replacement deletes the old provider plan first. Cancelled subscriptions cannot be resumed. Mutation retries are disabled.{{/stripe}}

Offline contract and OpenAPI exports do not require live database or provider settings. Add custom routes under `src/routes`. Compliance export/erasure require a `system`-role JWT. The current TS billing entities classify all fields as non-PII, so these endpoints report no classified data with HTTP 404. Provider payloads and session URLs remain encrypted in native storage.

{{#stripe}}Direct `POST /webhook` callbacks verify the exact raw JSON body against optional `STRIPE_WEBHOOK_SECRET`; absent credentials reject the callback. Managed `POST /platform-events/payments` callbacks verify the instance HMAC key, platform key ID, path, raw body and five-minute clock skew. Set `INSTANCE_HMAC_KEY` for this surface. Nonces are claimed atomically across replicas and retained for ten minutes to cover future-dated credentials. Grant SELECT/INSERT on `fl_billing.webhook_receipts` and SELECT/INSERT/DELETE on `fl_billing.platform_event_nonces` to the runtime role.

Successful Stripe event receipts persist across restarts and are shared by direct and platform delivery. Concurrent duplicate processing returns 503 for retry. Failed events remain retryable. Receipts retain only identity/type metadata; provider calls and business writes precede receipt commit, so interrupted external/local effects still need reconciliation. Product updates visit bounded provider pages; unsupported event types are acknowledged and recorded. Current TS portal-event expiry treats provider seconds as milliseconds, and payment-link events use CREATED/UPDATED status strings; these compatibility quirks remain tracked for semantic review.{{/stripe}}
