Checkout session `uri` is optional in the create and response schemas (Zod and TypeBox), and Stripe checkout creation no longer requires `stripeFields`. Stripe Checkout Session URLs are nullable, so a session without a provider URL is now an omitted `uri` rather than a validation failure. Callers must check `session.uri` before redirecting. The generated billing-stripe module already maps a database `NULL` to an omitted `uri`; applications that persist sessions need the `checkout_session.uri` NOT NULL constraint dropped first (see `blueprint/billing-stripe/CHECKOUT_URI_MIGRATION.md`).

This release also carries the unreleased billing hardening on the branch: cached checkout, portal and payment-link reads are bound to the requested identity, provider responses are validated before local persistence, and provider identity is verified before provider updates and before read results are attached.

Without this release, apps generated by the CLI fail to build: the billing-stripe module's checkout response mapper returns an optional `uri`, which the published 1.2.13 schema rejects (TS2719 in `checkoutSession.mappers.ts`).
