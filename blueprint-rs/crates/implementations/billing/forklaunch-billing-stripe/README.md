# Stripe billing

`StripeBillingClient::verify_context(expected_account, expected_livemode)` verifies a direct account using authenticated `GET /v1/account` and `GET /v1/balance`. Expectations must come from trusted server configuration. The account response must match the expected account ID and the balance must explicitly report the expected boolean mode. No account or mode is inferred from API key prefixes. Restricted keys without both read permissions fail closed. Requests use the client's existing bounded HTTPS/trusted-proxy transport and pinned API version; no Connect account header or provider mutation is added.

The returned `VerifiedStripeContext` has no public constructor, clone or serializer. `ensure_current` requires the same immutable client generation and less than five seconds elapsed since verification started. A cloned client retains the generation; a newly constructed client or version reconfiguration requires verification again. Future binding lookups/provider mutations must obtain fresh verification for each operation and recheck immediately before use. This observed context is not a financial-operation capability, proof of local ownership, or guarantee that a remote credential/proxy has not changed after the reads. Existing billing wrappers are not yet gated by this API.

Managed verification returns `billing_managed_context_unavailable` before any request. The companion platform's payments allowlist excludes `/v1/account` and `/v1/balance`; its gateway resolves `stripeAccountId` for each call and forwards `Stripe-Account`, but returns no authenticated account/mode/binding-generation contract. Expanding that protocol requires deliberate platform and mock changes with generation/rotation checks. This implementation does not weaken the allowlist or substitute the instance ID for a Stripe account.

Provider definitions: [account retrieval](https://docs.stripe.com/api/accounts/retrieve), [balance retrieval](https://docs.stripe.com/api/balance/balance_retrieve), and [balance mode](https://docs.stripe.com/api/balance/balance_object). The repository's pinned official Stripe SDK uses `/v1/account` for `accounts.retrieve()` without an ID, and `/v1/balance` for `balance.retrieve()`; the owned SDK/native oracle checks both requests.
